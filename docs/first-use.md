# 本机首次使用

双击运行包中的 Launch.cmd 或 启动软件.cmd。模型首次准备最多等待 180 秒；普通评估默认预算 3 秒。主口令仅在软件建库/解锁界面输入。

第一次可双击“首次配置.cmd”，它注册本机浏览器宿主，打开软件和这份说明。你的正常浏览器配置需要手动加载插件；验收使用独立测试配置，没有修改你的个人账号或已有口令库。

1. 在软件中创建自己的 KDBX 口令库，设置主口令并保存到本机文件。
2. Chrome 打开 chrome://extensions，Edge 打开 edge://extensions，开启开发者模式，选择“加载已解压的扩展程序”，均选择运行包内的 extension-chromium 文件夹。扩展 ID 应为 ijlckofhohjbbifcfhpiglkmfndaaeol。
3. register-browsers.ps1 为本机注册 Native Messaging。若更换运行包路径，重新运行它。
4. 在 HTTP(S) 网站打开扩展，点击连接，并在软件中批准关联自己的口令库。
5. 在扩展中选择新建/修改场景和目标账号；新建时填写账号名称。有多个账号时先选择原目标。按网站规则调整长度、字符类别及禁用字符。

已有账号的登录列表可点击“口令风险评估与改密”进入面板；网页生成图标也会打开面板。旧保存横幅的新增/更新操作先准备候选，再在面板完成网站成功后的确认，风险模式不允许旧 set-login 绕过确认。
6. 评估显示六档 PSM 估计区间或截断下界，PARD 重用结果独立显示。当前效果映射未冻结，待验证结果不会宣称低风险。
7. 生成与复检后将候选填入新口令及确认框。识别不可靠时，在扩展中手动选择“目标输入框”。
8. 网站明确报告注册/改密成功后，勾选网站成功与待验证确认，再点击保存。软件实际保存 KDBX 成功后才报告完成。
9. 重访网站可按原填充流程选取账号。锁库、切库、切换账号、修改输入或取消会使待保存候选失效。

桌面编辑器的“模型风险评估”页和数据库报告的“模型风险报告”页均可异步评估。推荐默认生成 20 位，最多尝试 20 次；普通预算不足时返回未知，可主动延长推荐预算至 120 秒。

GitHub CPU 软件包存在历史口令时，生成前请主动选择“30 秒（显式延长）”；历史较多或 CPU 较慢时可选择 120 秒。默认 3 秒超时会返回未知且不准备候选，等待恢复后再明确选择较长预算重试。搜索宽度不会自动降低。

桌面生成候选后，先完成网站操作，再勾选两项确认并将候选交给条目编辑器；确认条目编辑后按 Ctrl+S 保存 KDBX。数据库报告页评估选中条目时会排除该条目自身与自身历史。

check-environment.ps1 只检查文件、版本、CUDA 可用性和 Native Messaging 注册，不读取口令库。GitHub Release 的 Windows x64 包已包含独立 CPU 推理环境和中性命名模型；本机原 CUDA 运行包仍可使用。
