# 项目完备性与可用性审计

审计日期：2026-10-06。范围：本地工作区、GitHub 主分支、现有 Windows 演示目录及 `PROMPT.md` 的功能要求。

## 结论

当前是已有桌面、浏览器扩展、算法服务和 MCP 演示组件的开发原型，尚不是功能完整、可直接交给队员安装使用的产品。本机当前配置下，算法服务启动失败；风险等级标定、推荐约束、首次保存和确认保存的条目绑定仍存在实现缺口。历史构建成功记录不能替代当前运行和端到端验收。

项目不需要新增账号服务器、网页产品、多端同步或扩展商店发布；这些不属于首期交付范围，不作为本次缺陷。

## 已复核的阻塞和实现缺口

### P0：当前算法服务无法启动

指定解释器为 `D:\Anaconda3\envs\pytorch_cuda\python.exe`。本次模块检查结果：

| 模块 | 实测 |
| --- | --- |
| numpy | 1.26.2，可导入 |
| torch | 2.8.0+cu129，可导入 |
| tomli | `ModuleNotFoundError` |
| torch_geometric | `ModuleNotFoundError` |

默认配置探测约 4.45 秒后观察到进程退出码 1，未进入 ready。进一步使用 `--no-warmup` 隔离模型加载，仍退出码 1、stdout 零行；异常类型为缺少 `tomllib` 后缺少 `tomli`。Python 3.9 需要后者。即使补齐 TOML 依赖，PARD 仍需要 `torch_geometric`。

这与 2026-09-22 的历史环境记录不同，须以当前实测为准。此次未安装依赖或修改现有环境。

### P0：确认保存没有绑定原条目

`browser-extension/extension/background/keepass.js:295` 的暂存对象仅保存候选、输入修订、来源和时间，没有保存评估时的条目 UUID 或数据库会话。`:341` 在用户确认时重新取得当前所选条目。

本次使用 Node VM 加载这段原有函数、模拟浏览器和条目状态：生成时选中 `entry-a`，随后改选 `entry-b`，确认返回 `OK`，实际更新目标为 `entry-b`。这证明“生成后切换账号”会更新另一条目。该复现属于函数级验证，不是实际浏览器验收。

需要把候选与原条目、口令库会话、来源和输入修订共同绑定；任一变化须拒绝旧候选或重新评估。

### P0：新增条目的风险闭环不完整

同一函数级复现中，当前站点无已有条目时，暂存返回 `OK`，确认保存返回 `UNAVAILABLE/NO_SELECTED_ENTRY`。`:328` 的确认函数只支持已有条目更新。

原有 `addCredentials` 流程仍可创建条目，但它直接调用 `updateCredentials`，没有接入风险评估和候选确认流程。因此不能把原有新增功能视为“首次评估 → 推荐 → 复检 → 确认新增”已经实现。

### P0：风险标定尚无可加载的完整映射

`desktop-app/src/riskassess/RiskAssessmentService.cpp:329` 固定写入 `calibrated=false` 和 `level=UNKNOWN`，仅精确重用映射 `HIGH/EXACT_REUSE`。目前没有 `RiskMapper` 或 `share/riskassess/risk-thresholds.json` 的实现。

保留 UNKNOWN 符合安全边界，但也意味着普通拖网结果和非精确重用结果不能形成需求中的风险等级。补齐需要既有实验结果、版本/配置绑定的标定文件以及读取和映射代码，不能只导入一个阈值文件就视为完成。

### P1：推荐功能没有完成约束与达标筛选

`:404` 直接读取全局 `PasswordGenerator` 设置并生成一次候选；`:444` 固定 `attempts=1`；正常复检后固定返回 `REVIEW_REQUIRED`。扩展和宿主推荐动作均未传入网站最小/最大长度、必需字符类或禁用字符。

当前没有网站约束检查、失败重试、共享总预算和经独立阈值判定的 `QUALIFIED` 路径。原有 `generatePassword` 动作仍走原生成流程，也没有自动接入新增风险复检。已有推荐按钮不等于安全推荐功能完整。

### P1：历史选择不能保证改密时纳入当前旧口令

`collectHistory` 在 `:260` 开始，按全部条目修改时间排序后最多取五个；只有 `audit` 排除自身的分支，没有 `change` 强制纳入当前条目的分支。当前条目较旧且有五个更新的不同口令时，它可能被截掉，遗漏最相关的旧口令。也没有读取 `Entry::historyItems()` 中的历史快照。

这属于静态代码确认；须用数据库对象测试覆盖当前旧口令优先、历史快照、重复值、越域和审计排除自身。

### P1：用户展示和故障反馈不完整

- `popup.js:158` 的结果展示只显示简短结论，没有呈现 `native.guess_number`、`best_rank`、模式、历史使用计数和评估时间。文案“模型已返回原生指标”不等于用户能看到这些指标。
- 没有桌面条目编辑风险徽章或个性化风险报告页；扩展选项页未发现风险开关与标定展示。
- 新增风险面板文案直接硬编码中文，没有按规格接入 `_locales`。
- 多数后台提前失败响应不带 `inputRevision`，而 `popup.js:192`、`:207` 会因此直接丢弃回复，可能停留在“正在评估/生成”。
- 改密页填充目前选择活动密码框或第一个密码框（内容脚本 `:935`）；旧口令、新口令和确认框的真实页面行为尚未验收。

### P1：浏览器连接和独立分发未完成

本次读取 Chrome、Edge、Firefox 的 HKCU、HKLM、HKLM WOW6432Node 共九处标准 Native Messaging 注册位置，均未发现 `org.keepassxc.keepassxc_browser` 注册项。检查未修改注册表；也未完成真实扩展关联。

演示包配置明确引用 `D:/研究生/网络安全竞赛/RankGuess拖网猜测/` 和 `PARD定向猜测/`，启动脚本默认使用开发者 Conda 解释器。队员仅复制目录不能获得这些路径和环境。

根目录 `forsure_product.zip` 是 2026-09-20 的源码/权重归档：1,622 个条目、零个 EXE，没有 `algo-service` 和当前浏览器扩展。它不是当前产品安装包。模型来源及再分发条件仍沿用 DIST-01 的待核实事项。

### 其他规格偏差

- `Config.cpp:191` 的风险评估开关默认值为 `true`，与 `PROMPT.md` 默认关闭的要求不同。
- `src/riskassess/` 目前只有一个服务类，并被编入 browser 静态库，没有独立风险构建开关或规格中的独立核心库。
- 生成提供器配置尚未接入桌面推荐链；宿主始终使用原随机生成器。服务注册表具备扩展结构，但不能据此认定生成提供器切换已验收。

## 补齐和验收顺序

1. 恢复并记录 Python 依赖，复核 CLI/GUI 启动；使用少量虚构输入验证真实 RankGuess 和非精确 PARD 请求。
2. 修复候选与条目/数据库会话的绑定；接入新增条目和既有保存/生成入口的风险流程。
3. 补齐历史选择、网站约束、重试和总预算；读取绑定模型与推理配置的标定文件。
4. 补齐原生指标、模式、错误反馈和必要桌面入口，增加业务层和扩展风险流程测试。
5. 在 Chrome 完整验收“建库 → 关联 → 首次保存 → 变体评估 → 推荐复检 → 网站成功确认 → 保存 → 回访填充 → 锁库”，再复核 Edge 和异常场景。
6. 制作使用包内路径、明确依赖和模型获取方式的版本化分发包，记录校验清单及另一台队员机器的安装运行证据。

只有完成这些实际验收后，才能把对应组件从开发原型改称功能完整、可交付使用。
